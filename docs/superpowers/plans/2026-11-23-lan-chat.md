# LAN Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a complete, defense-ready Python peer-to-peer LAN chat satisfying Tasks 1-4 and all general requirements in the assignment.

**Architecture:** A shared broadcast socket carries discovery and general traffic while a per-process unicast socket carries presence responses, conflicts, and encrypted private traffic. Focused protocol, crypto, peer-state, logging, and application modules keep the behavior explainable and independently testable.

**Tech Stack:** Python 3.10+, standard-library `socket`/`threading`/`json`/`logging`, `cryptography` Scrypt and ChaCha20-Poly1305, `unittest`.

**Spec:** `docs/superpowers/specs/2026-11-23-lan-chat-design.md`

## Global Constraints

- Use the socket API directly; do not use `socketserver` or chat, messaging, RPC, or discovery frameworks.
- Every user message is exactly one UDP datagram and has at most 500 characters.
- Every wire datagram is at most 1400 bytes; invalid input is dropped and logged without crashing.
- General traffic is broadcast and unencrypted; private traffic is unicast and authenticated-encrypted.
- Heartbeats use 5 seconds, expiry uses 15 seconds, and discovery completes within 1 second.
- Several peers must work both on one computer and on different computers on the same LAN.

## Review Focus

- A 500-character multibyte message that exceeds 1400 encoded bytes must be rejected before send (Task 1 test).
- Random, truncated, oversized, unknown-type, and schema-invalid datagrams must be dropped and logged without killing a receiver (Task 1 test).
- Simultaneous duplicate names must converge deterministically so exactly one peer continues (Task 3 test).
- An expired/stale endpoint may lose a UDP private message without an immediate error; the app must remain healthy and document the limitation (Task 4 test/docs).
- Ciphertext, nonce, or authenticated metadata tampering must be rejected without displaying plaintext (Task 2 test).
